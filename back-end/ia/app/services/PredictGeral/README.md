# PredictGeral — previsão de parâmetros da água

Estrutura inicial para prever valores futuros a partir das coletas históricas enviadas pela API. **Esta pasta ainda não implementa a previsão** e não exige treinar um modelo por corpo hídrico. A primeira versão deve usar uma referência estatística calculada no momento da requisição. Um modelo global, treinado uma vez com dados de vários corpos hídricos, pode ser acrescentado apenas se superar essa referência em testes cronológicos.

## Fluxo de implementação

1. **Definir o contrato (`schema.py`).** Receber uma lista de coletas do mesmo corpo hídrico, cada uma com data, ponto/profundidade quando disponíveis e parâmetros com suas unidades. Receber o horizonte em dias (inicialmente 7 ou 15). Devolver data-alvo, valores previstos por parâmetro, unidade, método usado e informações de confiabilidade. pH, oxigênio dissolvido e os demais parâmetros devem ter previsões independentes; ausência de um deles não deve impedir os outros.
2. **Preparar as coletas (`preprocessing.py`).** Validar datas e números, padronizar unidades, ordenar cronologicamente, resolver duplicatas e separar séries por ponto/profundidade para não misturar contextos diferentes. Preservar valores ausentes como ausentes; nunca inventar uma coleta intermediária. Rejeitar ou sinalizar histórico sem medições válidas.
3. **Construir o histórico disponível (`features.py`).** Para cada parâmetro, obter última medição, idade dessa medição, variação recente e intervalos reais entre coletas. Usar somente observações anteriores à data da previsão. Não supor que as coletas sejam diárias ou regulares.
4. **Calcular a referência (`baseline.py`).** Começar com persistência (último valor observado). Comparar uma tendência robusta baseada nas coletas recentes, com limites para evitar extrapolação excessiva; adotá-la somente se melhorar a validação. Com histórico insuficiente, manter persistência e sinalizar baixa evidência, sem afirmar uma confiança numérica não medida.
5. **Orquestrar a previsão (`predictor.py`).** Executar preparação, extração do histórico e método escolhido para cada parâmetro e horizonte. A data-alvo é a data de referência mais o número de dias solicitado. Retornar indisponibilidade para parâmetros sem histórico, em vez de preencher valores arbitrários. Nesta etapa, não criar rotas nem acessar banco de dados.
6. **Validar (`evaluation.py`).** Fazer backtests: em cada data histórica, ocultar coletas posteriores, prever 7/15 dias e comparar com uma observação futura dentro de uma tolerância temporal explícita. Registrar quantidade de pares, distância real ao horizonte e MAE por parâmetro/horizonte/corpo hídrico. Não usar divisão aleatória. Só substituir a persistência por outro método após melhora demonstrada em dados futuros.
7. **Evoluir, se houver dados suficientes.** Treinar um único modelo global fora da requisição com históricos de vários corpos hídricos. Na inferência, extrair as mesmas variáveis das coletas recebidas. Comparar o modelo global com a referência, inclusive em corpos hídricos não vistos no treino. Reaproveitar o padrão de artefato e manifesto do serviço de metais, sem reutilizar seu modelo de valores da coleta atual.

## Ordem mínima de entrega

Implementar `schema.py` → `preprocessing.py` → `features.py` → `baseline.py` → `predictor.py` → `evaluation.py`. Adicionar testes para coletas fora de ordem, datas duplicadas, lacunas, parâmetros ausentes, unidades incompatíveis e ausência de observação próxima ao horizonte. A previsão de 7 ou 15 dias só deve ser apresentada como validada se houver pares históricos suficientes nesses prazos.
